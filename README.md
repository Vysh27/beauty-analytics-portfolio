# Beauty E-commerce Analytics Portfolio

Four end-to-end analytics projects in a beauty / e-commerce context, each built
to mirror the kind of work a business-analytics team owns: predictive modelling,
customer segmentation, demand forecasting, and experimentation — plus a set of
production-style SQL reporting queries.

All data is **synthetic** (generated by the included scripts with fixed seeds),
so every project is fully reproducible with no private data. Each project is
self-contained: generate the data, run the analysis, inspect the outputs.

## Projects

| # | Project | Technique | Headline result (synthetic) |
|---|---------|-----------|------------------------------|
| 01 | [Customer churn prediction](01_churn_prediction) | Logistic Regression & Gradient Boosting, permutation importance | ROC-AUC **0.88**; flags the top-risk 20% of the base for retention |
| 02 | [Customer segmentation](02_customer_segmentation) | RFM + K-means, silhouette-selected k | 4 segments; **Champions = 19% of customers, 56% of revenue** |
| 03 | [Demand forecasting](03_demand_forecasting) | SARIMA & Holt-Winters vs seasonal-naive baseline | SARIMA **MAPE 9.3%**, beating the baseline's 13.7% |
| 04 | [A/B test analysis](04_ab_test_analysis) | Two-proportion z-test, Welch's t, power analysis | PDP redesign **+16% conversion**, p = 0.0003; +17.5% revenue/user |
| 05 | [Sales dashboard](05_sales_dashboard) | Streamlit + Altair, interactive filters | Self-serve KPI tiles, trend, category/segment/channel breakdowns |
| — | [SQL reporting queries](sql) | Window functions, CTEs, cohort retention, reusable view | Daily/hourly category trackers + retention cohorts |

## Why these

They map directly onto the Analyst II (Analytics) responsibilities: applied
predictive modelling (churn, segmentation, forecasting), designing and reading
A/B tests with proper statistical rigour, an interactive dashboard for self-serve
reporting, and the recurring MIS / category reporting that SQL powers. Tools used
— Python (pandas, scikit-learn, statsmodels, scipy), Streamlit, SQL — are the
ones the role runs on.

## Quick start

```bash
pip install -r requirements.txt

# run any project (data generation first, then the analysis)
cd 01_churn_prediction
python generate_data.py      # writes data/customers.csv
python churn_model.py        # trains, evaluates, writes outputs/
```

Each project's `outputs/` folder holds the charts and result CSVs produced by
the run. See the per-project README for the full walkthrough and how to read the
results.

## A note on the data

Every dataset is fabricated with documented, realistic relationships baked in so
the models have genuine signal to recover — but the numbers describe no real
company or customers. The point is to show the *method* end to end, honestly
back-tested, not to claim real-world results.
